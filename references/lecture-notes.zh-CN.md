# 大模型是怎么造出来的：一份可核对的技能笔记

> 来源：Yann Dubois 在斯坦福 CS229《机器学习》2024 年夏季的客座课 *Building Large Language Models*（Stanford Online 发布于 2024-08-27，全长 1:44:31）。本篇是学习笔记，不是官方材料。

这份笔记解决一个问题：**当有人跟你说"我们做了个模型/我们微调过了/我们某个榜单 92 分"时，你能不能立刻判断这句话有多少含金量。**

## 一句话结论

造模型有五个部件：架构、训练目标、数据、评测、系统。学界卷前两个，工业界真正拉开差距的是后三个——**数据、评测、系统**。

## 五部件

| 部件 | 一句话 | 谁在卷 |
|------|--------|--------|
| 架构 | Transformer 及其变体 | 学界（实践中最不关键） |
| 训练目标/算法 | 下一词预测、优化器 | 学界 |
| **数据** | 抓到什么、怎么洗、怎么配比 | 工业界 |
| **评测** | 怎么知道真的变好了 | 工业界 |
| **系统** | 怎么让几千张卡跑起来 | 工业界 |

## 预训练：把互联网压进模型

**分词器（06:51）**：文本切成子词 token；同一句话在不同分词器下 token 数不同，直接决定成本与效果，代码、数学、中文差异最大。

**数据管线（28:51）**——这是全课最实用的部分：

1. Common Crawl 起手：约 2500 亿页、约 1 PB；
2. HTML 抽正文（公式、页眉页脚是难点）；
3. 过滤不良内容（NSFW、有害、PII：黑名单 + 小分类器）；
4. 去重（页眉页脚、同内容多 URL、重复段落）；
5. 规则过滤（token 分布异常、词长异常、过短过长）；
6. 模型过滤（用"被维基百科引用的网站"当正样本训分类器）；
7. 领域配比（代码、书籍加权；娱乐降权；代码多有助于推理）；
8. 收尾用高质量数据 + 降学习率（相当于在维基上"过拟合"）。

团队规模感：Llama 团队约 15 人做数据，比做模型的人还多，但更吃 CPU（37:02）。

**规模定律（40:39）**：损失随参数/数据/算力呈幂律下降，小模型拟合后可外推。Chinchilla 的结论是每参数约配 20 个 token 更划算（51:37）。

## 后训练：把"续写机"变成"助手"

**SFT（62:03）**：拿人写的"问题→理想回答"继续做下一词预测。关键洞察：**它只教格式和人格，不教知识**。LIMA 把数据从 2,000 条加到 32,000 条，提升几乎为零（65:31）。副作用是模型学会"编一个像样的答案"，幻觉有一部分源于此（72:06）。Alpaca 用 175 条人写种子生成 52,000 条（64:03）。

**RLHF（72:29）**：同一问题出两个回答 → 人标哪个更好 → 训奖励模型（Bradley-Terry，输出连续分数）→ 用 PPO 优化，并加正则防止把奖励模型"刷爆"。二元奖励太稀疏，不知道"好多少"（74:11）；PPO 工程上极易翻车（79:00）。

**DPO（79:41）**：不用强化学习，直接拉高偏好答案的概率、压低不偏好的；标准假设下最优解与 PPO 等价，实现简单得多，现在是开源与工业界的主流之一。

**标注经济学（83:47）**：人对自己的标注只有约 66% 一致率（论文作者自己标也只有 67–68%）；人工约 $300/1000 条，大模型当标注员便宜约 50 倍，且与"人类多数意见"的一致率更高。偏差：偏好长答案 → 模型越训越啰嗦（84:55）。

## 评测：为什么这块最容易自欺

- **验证损失不可比**：PPO 和 DPO 优化目标不同（88:05）；
- **困惑度失效**：经过 PPO 的模型是"策略"，不再是对文本分布建模（89:10）；
- **Chatbot Arena**：真人盲测两两比，最可信，但慢、贵、用户偏技术圈（90:05）；
- **模型当裁判**（AlpacaEval）：与 Arena 相关性约 98%，**不到 3 分钟、不到 $10** 跑完（91:46）；偏差是偏爱长答案和同族风格。

**实用规则**：看到任何分数，先问三件事——用什么基准、和谁比、裁判是谁。

## 系统层

- **混合精度**：权重 32 位存、16 位算、32 位更新；深度学习噪声本来就大，精度损失可以忽略（100:05）；
- **算子融合**：每次 PyTorch 操作都往显存搬运数据，融合后搬一次算完；`torch.compile` 能让训练快约 2 倍（102:37）。

## 五个常见误读

| 误读 | 纠正 |
|------|------|
| 微调能把业务知识教进去 | 主要教说话方式；要新知识，靠检索或继续预训练 |
| SFT 数据越多越好 | 几千条好数据之后基本不涨 |
| 困惑度/损失降了就说明变好了 | 偏好训练之后这两个指标不再说明问题 |
| 换个新架构是主要抓手 | 工业界真正决定效果的是数据、评测、系统 |
| "我们榜单赢了 X" | 先问基准、对手、裁判三件事 |

## 怎么用

- **写解说**：按"五部件 → 预训练 → 后训练 → 评测"讲，每段给一个反直觉点（SFT 不教知识 / ChatGPT 话多源于标注偏好 / 困惑度失效）。
- **判断宣称**：三问法（基准、对手、裁判）；答不出来，数字基本不可信。
- **给客户解释**：微调≈教说话方式；要私有知识，先上检索。
